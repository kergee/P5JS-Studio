# PCD 2026 中文分享讲稿与演示

题目：从学生作业归档到离线创作：P5JS Studio 的开发实践

时长：18 分钟分享，预留 2 分钟交流。讲述自己的开发过程，教学效果仅用实际观察，不编造班级数量、学生反馈或节省时间的数据。

## 0:00–2:00 开发起点

大家好，我是张科技。我开发了一个开源桌面工具 P5JS Studio。最初的需求来自两个很具体的场景：离开网络后还能继续创作，以及把学生提交的 p5.js 作业集中整理、方便查看和长期保存。

在线编辑器让大家容易开始写程序，但课堂网络条件并不总是稳定。作品提交以后，代码、图片、声音和不同版本又可能散落在不同文件里。我希望作品保存下来以后，过一段时间仍然能打开、运行和继续修改。

## 2:00–4:00 项目的使用流程

图库按文件夹组织作品，例如“演示班 / 第一次”。每件作品保存自己的代码文件、资源、笔记和运行版本。这里的 ABC、DEF、GHI 都是演示代号，不是真实学生资料。

学生写完一个项目，导出该项目的 ZIP。教师把多个 ZIP 导入当前分类，遇到重名可以保留两份或跳过。归档完成以后，仍然可以回到编辑器继续创作。

## 4:00–8:00 离线编辑与多文件演示

打开 ABC。它有 utils.js 和 sketch.js，标签顺序就是拼接顺序。点击运行，修改一个颜色，再保存。展示笔记、调试台和缩略图。

打开 DEF。图片和声音放在 assets 中，代码使用相对路径。资源面板能添加文件并复制路径，避免必须去系统文件夹手动放素材。点击画布播放声音，说明声音播放需要用户点击，这是浏览器的音频规则。

现场使用本地文件和内置库。作品如果仍引用在线 API 或未下载的模型，就仍会需要网络。离线能力要看整件作品的依赖是否完整。

## 8:00–11:00 项目 ZIP 与教师归档

从 DEF 导出项目 ZIP。在另一分类导入，打开并运行，展示图片、声音、笔记和版本仍在。再次导入演示同名保留两份。

说明“导入项目”和“恢复备份”的区别：前者收作业，默认不覆盖；后者恢复整个目录包，会确认覆盖并先生成完整备份。分类导出保留班级层级，便于之后回到原来的位置。

导入成功只能证明结构合规、文件写入成功。作品是不是正确，还要运行和检查交互。动态路径和外部依赖让“自动保证所有作品可运行”成为一个不能随便承诺的事情。

## 11:00–14:00 p5.js 多版本

项目在 meta.json 里保存具体 p5.js 版本。编辑器下拉框控制当前项目，全局设置只影响新项目。老项目缺少字段时，用当前内置的 1.x 版本作为默认，在下次保存时写入。

展示 GHI 的 2.3.4 版本和异步资源加载。这里我为两个版本配置了各自的本地声音库。换版本不会自动改代码，例如 1.x 的 preload 和 2.x 的异步用法就需要区别处理。暂时关闭 2.x 中面向 1.x 的补全提示，避免给出错误建议。

## 14:00–16:00 保存和长期保留

修改笔记，返回图库，展示保存、放弃、取消。取消后继续编辑。项目重命名会随保存移动整个目录，资源不会丢掉。保存失败会显示错误并保留编辑内容。

我更关心作品能否在之后重新打开、重新运行和再次创作。版本信息、资源、备注、素材来源都属于作品的一部分，只有一个 JS 文件往往不足以保留完整语境。

## 16:00–18:00 当前局限与后续方向

目前优先支持 P5JS Studio 自己导出的项目包。任意 HTML 压缩包往往有脚本顺序、外部库、DOM 和资源路径的问题，直接提取 JS 不保证能运行。

我把在线大模型 API 辅助转换放在后续路线中。模型可以提出迁移方案，但需要让用户看差异、确认修改，并通过结构检查和实际运行验证。它会作为可选功能，离线编辑和归档不会依赖它。

项目已经开源。我希望和创意编程教育者、创作者交流：大家收作业时遇到哪些困难，哪些信息应该和作品一起保留，以及我们怎样让过去的课堂实验更容易重新发现。

项目链接：https://github.com/kergee/P5JS-Studio

## 现场演示清单

1. 预先导入 examples 的三个 ZIP，准备一个空的“演示班 / 第二次”目录。

## 可能的问题

**和在线编辑器有什么区别？** 侧重点是离线桌面使用、本地目录归档、完整项目包和版本记录。

**能保证所有导入作品都能运行吗？** 不能。结构校验和实际运行是不同阶段，外部依赖及版本差异需要单独检查。

**是否依赖 AI？** 当前离线编辑、资源管理和归档不依赖 AI。后续可能增加可选的在线转换助手。

**为什么需要具体版本？** 保存作品当时的运行环境，减少未来默认版本变化造成的意外；仍需验证代码本身的兼容性。

**真实学生作品可否公开？** 公开前确认学生授权并检查项目内的个人信息与素材许可。当前随仓库提供的是虚构演示项目。

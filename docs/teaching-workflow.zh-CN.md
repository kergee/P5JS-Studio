# 学生提交与教师归档

## 学生准备项目

1. 新建草图，在 p5.js 下拉框选择课程规定的版本。
2. 多个 JS 在标签栏添加，文件按标签顺序拼接运行。依赖函数所在文件应在调用它的文件之前。
3. 在“资源”添加图片、声音、字体或数据文件。复制相对路径，例如 assets/card.svg，填入代码。
4. 运行并确认输出、调试台和交互正确。声音通常需要点击画布才能开始。
5. 在笔记记录作品说明、素材来源和运行方法。
6. 点击“导出项目 ZIP”，按照课程约定命名，例如 ABC-第一次.zip。导出前会先保存。

建议用课堂代号命名项目。需要公开展示时先检查文件、笔记、素材和共享 public 目录中的个人信息与使用许可。

## 教师收集项目

1. 建立“某班 / 第一次”等分类目录，在该目录打开“导入项目 ZIP”。
2. 默认目标就是当前目录，也可切换目标或新建分类。选择多个学生项目 ZIP。
3. 默认重名保留两份，方便比较修订作业；选择“跳过同名项目”可以避免重复收集。项目导入不提供直接覆盖。
4. 查看每个包的成功、跳过或失败结果。缺少代码或本地库、损坏元数据、路径无效会拒绝导入。
5. 打开作品并运行，验证本地资源和课程使用的版本。导入成功仅说明结构与写入成功，不代表代码和所有交互都正确。
6. 分类笔记可记录课程、批次和审阅说明，项目笔记可记录反馈。

## 归档与恢复

“导出当前文件夹”生成分类目录包。“备份全部”生成完整图库包。目录包通过“恢复备份 ZIP”恢复到根目录，合并并覆盖相同路径，本地其他文件保留。

恢复会先生成 before-restore 时间戳 ZIP，位于应用数据目录 backups 下，界面显示具体位置。它保留恢复前的原始文件。恢复不是目录镜像同步，不会清理旧文件。分类导出保留完整分类层级，例如“某班/第一次/ABC”，恢复后仍位于相同分类位置，且不包含其他班级的作品。

单项目 ZIP 根目录有 meta.json。目录备份根目录通常是多个分类或项目目录。这两种包使用不同入口，不要把单项目包当全库备份直接恢复。

## 多版本与离线边界

项目用 meta.json 的 p5Version 固定精确版本。缺少字段的老项目使用本版内置的 1.11.13，下一次保存写入。全局“设置”的默认版本只影响新建项目，不会批量改动存量项目。未知版本会保留记录并阻止运行。

本版内置 p5.js 1.11.13、2.3.4 和各自的声音库。外部库应下载并记录在 libraries 中。通过在线网址引用库、模型或 API 的作品仍依赖网络。换版本不会自动转换程序，1.x preload 与 2.x 异步资源 API 需要分别处理。

共享 public 普通资源会一并复制到单项目包，声明的共享库和模型按依赖打包。本地同路径文件优先。动态引用让精确判断未使用资源变得困难，因此导出可能包含多余共享素材，请提前检查。

## 保存规则

未保存修改在离开时提供保存、放弃、取消。失败会显示错误并保留编辑内容。重命名只有保存成功后才整体移动项目目录。删除 JS 标签也要保存才更新磁盘。资源添加和移除立即写入磁盘，离开时“放弃修改”不会撤销已完成的资源操作。
